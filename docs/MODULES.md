# Module map — where each rule lives and what it guards

This is the long-form module list that used to be the body of `AGENTS.md`. It moved here when `AGENTS.md` was cut to a map (the prompt loader shares a 28k budget across every rule file it loads, and a 27k `AGENTS.md` lost its Conventions past the clip). Nothing was dropped: every bullet below is the doctrine that was in the tracked file, kept as the per-module contract a change has to respect. Extend this file (or `HARNESS.md` / `ULW.md`) when a rule grows; keep `AGENTS.md` under its budget.

Dense on purpose — each bullet is one module's invariants in the project's own vocabulary (cycle, plan, item, Planner, Reviewer, verify, commit, wave). Read the bullet for the module you are touching before you touch it; the tests under `tests/<module>.test.ts` pin most of what is written here.

## Harness (`src/harness/`)

- `src/harness/` — hooks, goal, stop-guard, handoff-guard, proof-claim-guard, project-memory (do not weaken blocking Stop defaults; leftover this-cycle notes auto-archive, `/memory project prune`; the tracked `.forge/MEMORY.md` is merged into the local JSON store on load — mirror-only bullets become `import` records, archived ones stay archived)
- `src/harness/cycle/` — the **ULW plan-cycle driver** (`docs/ULW.md`): `state.ts` (schema-2 `ulw.json`: cycle / phase / `items[]` / `verifyCommand` / `cycles[]` / `ledger[]` / identity; a schema-1 wave sidecar loads `legacy` and disabled), `machine.ts` (`decideAtStop` — pure: plan / reanchor / close-cycle / verify / yield / release; stamps one ledger row per Stop with edit delta, tree movement, proof ran; `stuck_threshold` no-progress Stops close the cycle instead of releasing), `artifacts.ts` (`parsePlanArtifact` / `parseReviewArtifact` — labelled lines only, `Verify:` through the strict check harvest, `continue` with no items does not parse; `PLAN_COMPLETE_RE` is the executor's declared closer), `briefs.ts` (Planner brief = mandate / identity / one-line ledger of what shipped (title · direction · verdict · worth · commit — never the previous plan's body or Out-of-scope list) / last review's must-fix + architecture + `Worth: no` / unfinished items / user interjections / tree / guideline survey / stack checks + procedure ("use it" before source; rank by "would a user notice"; batch or leave; `fulfilled` with no mandate = leave it) + contract; Reviewer brief = plan + `git diff <cycleStartHead>` + untracked bodies + changed files + recent cycles' `Worth:` + verify command + duty (correctness, shape, persisted data / public surface, worth) + contract; plan admission / items-open / fix re-anchors), `orchestrator.ts` (`evaluateCycleAtStop` runs the action through an injected `CycleRuntime` — `runRole`, `runCheck`, `commit`, `seedTodos`, `admit`, git — and writes `cycles/<n>/plan.md` / `review.md` / `verify.log`; `ensureCyclePlanned` at turn start; Planner retried once, then `blocked`; fulfilment from the Reviewer reopens `missing` items; `fix_rounds` cap releases `fix-cap` with nothing committed; the close sequence is verify → review → verify → commit so the Reviewer reads a tree that passes and the gate covers its revisions; `resolveVerifyCommand` refuses an isolate as the gate; a Reviewer `blocked` or unparseable review closes the cycle with no commit; cycle 1's admission captures `verify.baseline.log`), `verify.ts` (harness-run check: `/bin/sh -c`, full output kept for the failure diff, tail 16k for the re-anchor, timeout `FORGE_ULW_VERIFY_TIMEOUT_MS`, classified like a model bash; `judgeAgainstBaseline` — green is exit 0 or "every failure was already in `verifyBaseline`"; `extractFailingTests` in `verification.ts` names node:test / TAP / jest / vitest / pytest / cargo / go / mocha failures; an unnamed red is red), `controls.ts` (`armCycle` / `disarmCycle` / `setCycleFlag` (`/cycle 0` = finish the open cycle then stop) / `requestReplan` / `setMaxCycles` / `setHumanPlan` / `requestCycleZeroOnSafetyValve`; `stopBlockTripsContinueCap` — unlimited cycling never trips the process cap; `cyclePreferredCheckCommands` merges the Planner's `Verify:` ahead of the stack table; `cycleKeepPaths` = plan item files for request-prune), `status.ts` (`ULW c3/5 EXEC 2/7` badge, `/cycle status` card, `cycleReportFacts` for the run report, `ulwCyclesCommittedFor` for metrics). No prose classifier anywhere: the Planner decides `fulfilled`, the Reviewer judges the diff, the harness enforces sequence and facts
- `src/harness/verify-command.ts` — leaf recogniser for "ran a check": `VERIFICATION_CMD_RE` (npm/pytest/cargo/go/swift/xcodebuild/zig/dotnet/dart/just/make/… + repo scripts `./build.sh` / `scripts/test.sh` / `--self-test`), quoted spans ignored, observer/arranger heads (`pgrep`, `echo`, `grep`, `rm`, `git`, `cat`) never count (`isObserverOnlyCommand`); `isVerificationCommand(cmd, preferred)` also matches preferred/declared checks as segments
- `src/harness/declared-checks.ts` — harvests a `Verify:` / `Proof:` / inline-code check command (`extractDeclaredChecks`, `looksLikeCheckCommand` — strict: allow-listed runner head or check-shaped script path; prose/observers/product verbs refused); the Planner's `Verify:` lands in `ulw.json.declaredChecks` and merges ahead of project-intel via `cyclePreferredCheckCommands` so any stack's check earns structural proof
- `src/harness/verification.ts` — one classification for every channel that observes a check run (`classifyVerificationRun`: ran / passed / isolate / fullSuite; `countsTowardVerification` refuses background spawns; `applyVerificationTrail` keeps the session's last-verify honest — red keeps the command, never "none"); `isFullSuiteCommand` / `isIsolateTestCommand` / `isTypecheckCommand` across npm / pytest / cargo / go / swift / …
- **Background verification credit** (`src/agent/loop.ts` + `src/agent/tools/background-tasks.ts`): a `background:true` check is proof when it settles (`onBackgroundTaskSettled`) or is joined by `get_task_output` — `classifyVerificationRun` (ran / passed / isolate / fullSuite from command + exit code + log tail) feeds the same counters and last-verify trail as a foreground result; one task credits once (`creditedBgTaskIds`); only the spawn observes nothing (`countsTowardVerification` still refuses starts). Dogfood ran 20/28 and 45/61 checks in the background as the doctrine says and stamped proof=✗ on every one
- `src/harness/decision-memory.ts` — session decision ledger; cap 400 with a load-bearing trim (`trimDecisionRecords`: superseded → waves beyond `WAVE_RECORDS_KEEP`=48 → oldest non-durable; `MANDATE:`, durable kinds and `Plan N:` rows never evicted — both 400-record dogfood runs had lost their mandate); `selectMemoryForPrompt` = durable rows + the last two plans + the newest notes
- `src/harness/context-admit.ts` — mid-conversation harness admissions (stable system + live counters; counter-only churn suppressed; volatile git branch line admitted append-only — message[0] keeps cache-stable git root/remote only)
- `src/harness/interjection.ts` — free-text mid-run messages (Grok-style `<user_query>`)
- `src/harness/todo-gate.ts` — TodoNudge + TodoGate under ULW (the plan items on the board gate Stop until `Plan complete.`); soft once outside ULW; `clearSoftTodoGateOnWindDown` on `/done`/`/goal done|clear`/`/ulw-off`/`/clear`/`/new` **and** fresh driver arm (`/ulw`, `/goal set`); advisory Q&A releases TodoGate + skips TodoNudge (pairs with compact ADVISORY framing)
- `src/harness/handoff-guard.ts` — premature “let me know if…” / “shall I continue?” Stop block (finish doctrine) · advisory Q&A allows soft continue-asks
- `src/harness/proof-claim-guard.ts` — “tests pass” / bare “Done.” after edits without *successful* verification (`verificationPassed`) Stop block (don't claim, prove) · advisory Q&A softens bare Done./Fixed. closers
- `src/harness/report-guard.ts` — closing message must stand on its own: directive homework hand-back (“you should run…”, “you'll need to…”) blocks once; affordances (“you can now…”) pass; after ≥ 2 harness rounds with edits the closer must be outcome-first with ≥ 2 labelled sections (any heading / short bold label); attestation pass ahead of the drivers; pinned to `tests/fixtures/prose-corpus.ts`
- `src/harness/guideline-audit.ts` — `AGENTS.md`-class files: fact defects (`stale-paths` / `stale-commands` / `pm-mismatch` / `clipped` / `empty`) are fixed in place by the model; doctrine (`long` / `conflict` / `no-commands`) goes to a proposal outside the repo (`/guidelines diff|apply|discard`, `guidelineAutoApply`); evidence-triggered (fact defect, or body changed + any issue); no Stop block; registry `~/.forge/guidelines/`

## Agent loop, tools, subagents (`src/agent/`)

- `src/agent/` — loop, tools, permissions, subagents (`spawn_subagent`; general-purpose defaults to `isolation=worktree` and auto-lands into parent only when status=completed; incomplete keeps the worktree, including `land=discard`; `resume_session_id` continues a kept child; explore skip is `skipped_explore_ledger`). Same-round explore/plan and worktree GP overlap with `web_search` (cap 8; `isolation=none` GP is serial; `FORGE_SUBAGENT_PARALLEL=0` off). PLAN/orient omitted type is explore. Native Imagine (`image_gen` / `image_edit` / `image_to_video`) + vision on `read_file` of images. Credential reads (`auth.json`, `id_rsa`, `~/.grok/auth.json`) are hard-denied — YOLO / `--read-outside allow` cannot dump tokens into the model.
- `src/agent/project-skills.ts` — skill packs: package `skills/forge-*/` (builtin) + `.forge/skills/**/SKILL.md` + `.agents/skills` + `~/.forge/skills` (project > user > builtin; `FORGE_BUILTIN_SKILLS=0` off)
- `src/agent/tools/file-read-state.ts` — session stale/unread edit guard (`FORGE_FILE_READ_GUARD=0` off); `refreshNotedFromDisk` restamps after apply_patch rollback so a retry is not "changed on disk"
- `src/agent/tools/edit-receipt.ts` — numbered AFTER receipt for search_replace/write_file/apply_patch (`FORGE_EDIT_RECEIPT=legacy` off)
- `src/agent/tools/ask-user.ts` — interactive clarifying questions (OpenCode-inspired)
- `src/agent/tools/format-on-write.ts` — format after file tools (`/format`, `FORGE_FORMAT_ON_WRITE`; auto when prettier/biome/ruff/… detected)
- `src/agent/sandbox.ts` + `rules.ts` + `shell-parse.ts` — OS sandbox, deny/allow/ask rules, segment-aware shell checks
- `src/agent/permission-preview.ts` — in-memory colored diff previews for edit-tool permission asks (never writes)

## Sessions, memory, wire (`src/session/`)

- `src/session/subagent-usage.ts` — parent family spend ledger (`meta.subagentUsage`); fold uses child.meta so completed explores cannot vanish; `/budget` is the family cap (children pin to remaining; parent HIT refuses spawn; live-fold so parallel siblings share remaining; cost-cap handoff is `incomplete_cost_cap` and does not land)
- `src/session/compaction.ts` — structured compact preserving mandate/goal/todos
- `src/session/checkpoint.ts` + `compaction.ts` — store checkpoint (job card + in-flight tail) when session.json is huge; not outbound-80k FullReplace
- `src/session/prompt-cache.ts` — xAI `x-grok-conv-id`, reasoning replay, cache ratio, prune-at-180k decision
- `src/session/explore-map.ts` — structured explore child maps; parent `read_file` dereference + cited-line window
- `src/session/request-prune.ts` — outbound working-set prune (default **off** until `min(180k, 55% of the route window)` so the prefix can cache on xAI 500k while Cursor Grok 256k clips before the host fills; first clip freezes a sticky omit set on `session.meta.requestPruneSticky`; later rounds apply that set instead of re-aging; `FORGE_REQUEST_PRUNE=1` legacy every-round)
- `src/session/tool-clearing.ts` — optional in-session stubbing (`FORGE_TOOL_CLEAR=1`; default off)

## Config and utilities (`src/config/`, `src/util/`)

- `src/util/git-auto-commit.ts` — `commitDirtyTree({ cwd, subject, body })`: the plan-cycle driver commits once per reviewed, green cycle (`ulw cycle N: <title>`; never push); `FORGE_ULW_AUTO_COMMIT=0` off. **Looks and scratch stay unstaged**: `isLookArtefactRelPath` (image/HTML whose name or dir says screenshot / look / shot / capture / preview / states / before / after) + `findUnreferencedAssets` (nothing tracked or untracked references the basename) → left out of the commit; `isForgeScratchRelPath` keeps `.forge/` to `MEMORY.md` / `AGENTS.md` / `hooks.json` / `config.toml` / `commands/` / `skills/` / `hooks/`; the result's `leftUnstaged` becomes one `formatLeftUnstagedAdmit` harness message naming `sessionLooksDir(sessionId)` (`~/.forge/sessions/<id>/looks`); a dirty tree of looks alone skips with `only look artefacts / scratch remain`.
- `src/config/model-info.ts` — per-model context windows (xAI grok-4.6/4.5=500k, grok-4=256k, claude=200k, gpt-4.1=1M; **Cursor-hosted Grok 4.5+ = 256k**, native 500k on xAI); Grok flagship ids newer than the last known milestone inherit that milestone (`src/config/grok-model.ts`)
- `src/util/advisory-intent.ts` — Q&A/advisory vs work-order classifier (compact handoff + mid-run interjections under ULW; guideline audit + report guard defer on it); work-order signals (polite/imperative/coordinated work verbs) win over a trailing `?`; pinned to `tests/fixtures/prose-corpus.ts`
- `src/util/cost-budget.ts` — session spend cap parse/resolve (`/budget`, `--max-cost`, `FORGE_MAX_COST_USD`)
- `src/util/production-warnings.ts` — `productionWarningsForRun` for `forge run --json` / CI (safety valves, ULW-without-budget, dirty tree, editsWithoutVerification, lockfile/node_modules)
- `src/util/project-intel.ts` — package manager + preferred check commands (system prompt, `/context`, bash wrong-PM/missing-script/missing-binary tips; monorepo walk-up + turbo/nx; Swift `Package.swift` → `swift build`/`swift test`, Zig, .NET, Dart/Flutter, executable repo check scripts `./build.sh` / `./test.sh` / `scripts/check.sh` (`localCheckScripts`); doctor/status/config/run JSON; last-verify trail + `editsWithoutVerification`)
